# ربات تولید محتوای اینستاگرام

بر اساس موضوع پیج شما پست می‌سازد: ایده، کپشن، هشتگ و تصویر آماده‌ی انتشار.

## سه حالت کار

### ▸ حالت `buffer` — پیش‌فرض، خودکار کامل بدون حساب متا

ربات محتوا را می‌سازد، تصاویر را روی یک آدرس عمومی آپلود می‌کند و پست‌ها را با
تاریخ و ساعت در صف [بافر](https://buffer.com) می‌گذارد. بافر اپ متای تأییدشده‌ی
خودش را دارد و سر ساعت روی اینستاگرام منتشر می‌کند.

```
ربات هفته‌ای یک بار ۷ پست می‌سازد
   ← تصاویر را آپلود می‌کند
      ← پست‌ها را با تاریخ در صف بافر می‌گذارد
         ← بافر هر روز رأس ساعت منتشر می‌کند
```

هیچ مرحله‌ی دستی‌ای نمی‌ماند. شما فقط اکانت اینستاگرامتان را یک بار در سایت بافر
وصل می‌کنید — با یک لاگین معمولی اینستاگرام، بدون هیچ سروکاری با `developers.facebook.com`.

```bash
python main.py channels             # ببین چه کانال‌هایی وصل است
python main.py schedule --count 7   # یک هفته
python main.py schedule --count 30  # یک ماه
```

**پیش‌نیازها:** کلید API بافر (از `publish.buffer.com/settings/api`) و یک مخزن
گیت‌هاب **عمومی** برای میزبانی تصاویر — چون بافر هم مثل اینستاگرام تصویر را از
یک آدرس عمومی برمی‌دارد.

### ▸ حالت `batch` — بدون هیچ سرویس واسطی

اگر نخواستید به هیچ سرویس واسطی وابسته باشید: محتوا ساخته و در تلگرام تحویلتان
می‌شود، و زمان‌بندی را خودتان در اپ اینستاگرام انجام می‌دهید (زمان‌بندی داخلی
اینستاگرام، تا ۷۵ روز جلوتر). حدود ۵ دقیقه کار در هفته.

```bash
python main.py batch --count 7      # یک هفته
python main.py batch --count 30     # یک ماه
```

### ▸ حالت `api` — انتشار کاملاً خودکار

اگر به پلتفرم متا دسترسی دارید، ربات می‌تواند خودش مستقیم منتشر کند. برای فعال
کردن، در `config.yaml` مقدار `mode` را روی `api` بگذارید. بقیه‌ی این فایل مربوط به
همین حالت است.

## چطور کار می‌کند (حالت api)

```
تقویم محتوایی  →  Claude متن می‌نویسد  →  Pillow تصویر می‌سازد
       ↓
آپلود روی فضای ابری (URL عمومی)
       ↓
Instagram Graph API: ساخت کانتینر → انتشار
       ↓
ثبت در SQLite + اطلاع‌رسانی تلگرام
```

هر روز نوع پست به‌صورت گردشی از `content_plan` انتخاب می‌شود؛ یعنی پیج شما یک روز
معرفی محصول دارد، روز بعد نکته آموزشی، روز بعد مقایسه و… و بعد از یک دور، دوباره از
اول. مدل زبانی عناوین ۳۰ پست اخیر را می‌بیند تا تکراری ننویسد.

## پیش‌نیازها

| مورد | توضیح | هزینه |
|---|---|---|
| اکانت اینستاگرام **Business** یا **Creator** | اکانت شخصی با API کار نمی‌کند | رایگان |
| اپ در Meta for Developers | برای گرفتن توکن | رایگان |
| کلید یک سرویس مدل زبانی | تولید متن | چند سنت برای هر پست |
| حساب گیت‌هاب | هم اجرای روزانه، هم میزبانی تصاویر | رایگان |

> **نکته مهم:** اینستاگرام فایل تصویر را از شما نمی‌گیرد. شما یک **آدرس عمومی**
> به آن می‌دهید و خودش دانلود می‌کند. به‌صورت پیش‌فرض این پروژه تصاویر را در شاخه‌ی
> `media` همین مخزن گیت‌هاب می‌گذارد و از `raw.githubusercontent.com` سرو می‌کند —
> پس به هیچ سرویس ابری دیگری نیاز ندارید. تنها شرطش این است که **مخزن public باشد**.
> اگر می‌خواهید مخزن خصوصی بماند، `storage.provider` را روی `s3` بگذارید و از
> Cloudflare R2 یا آروان‌کلود استفاده کنید.

## نصب

```bash
git clone <آدرس مخزن شما> insta-autopost
cd insta-autopost

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env      # مقادیر واقعی را داخلش بگذارید
```

سپس `config.yaml` را باز کنید و بخش `brand` را با اطلاعات پیج خودتان پر کنید.
اگر عکس محصول دارید، داخل `assets/products/` بریزید — پس‌زمینه‌ی تصاویر از آن‌ها ساخته می‌شود.
اطلاعات محصولات را در `catalog.json` وارد کنید؛ مدل فقط از همین‌جا قیمت و ویژگی برمی‌دارد
و از خودش چیزی نمی‌سازد.

## گرفتن دسترسی API (یک‌بار انجام می‌شود)

### ۱. اکانت را حرفه‌ای کنید
اینستاگرام → تنظیمات → نوع حساب → تبدیل به **حساب کاری (Business)**.

### ۲. اپ بسازید
به [developers.facebook.com](https://developers.facebook.com/apps) بروید →
**Create App** → نوع **Business** → داخل اپ، محصول **Instagram** را اضافه کنید و
گزینه **API setup with Instagram login** را انتخاب کنید.

### ۳. اکانت را وصل کنید و توکن بگیرید
در همان صفحه، **Add account** را بزنید و اکانت اینستاگرام خود را متصل کنید. سپس
**Generate token** — این توکن کوتاه‌مدت است.

`IG_USER_ID` هم در همان صفحه نمایش داده می‌شود (عددی و با `1784` شروع می‌شود).

### ۴. توکن را بلندمدت کنید
```bash
curl -X GET "https://graph.instagram.com/access_token\
?grant_type=ig_exchange_token\
&client_secret=<APP_SECRET>\
&access_token=<توکن_کوتاه_مدت>"
```
خروجی یک توکن ۶۰ روزه است. آن را در `.env` بگذارید.

### ۵. مجوزها را اضافه کنید
در بخش **App Review → Permissions and Features** این‌ها را اضافه کنید:
- `instagram_business_basic`
- `instagram_business_content_publish`

تا وقتی اپ در حالت Development است و اکانت شما نقش Admin/Tester دارد، بدون App Review
کار می‌کند. **اگر می‌خواهید فقط روی پیج خودتان پست بگذارید، نیازی به App Review ندارید.**
App Review فقط وقتی لازم است که بخواهید این ابزار را به کاربران دیگر بدهید.

### ۶. تمدید توکن
توکن ۶۰ روزه است. اسکریپت زیر را هفته‌ای یک‌بار در cron بگذارید:
```bash
./scripts/refresh_token_cron.sh
```

## میزبانی تصاویر

### پیش‌فرض: خود گیت‌هاب (بدون سرویس اضافه)
```yaml
storage:
  provider: "github"
  github:
    repo: ""          # روی GitHub Actions خودکار پر می‌شود
    branch: "media"
```
تصاویر در شاخه‌ی `media` ذخیره می‌شوند و آدرسی مثل زیر می‌گیرند:
`https://raw.githubusercontent.com/<کاربر>/<مخزن>/media/posts/2026/08/post_00042_01.jpg`

حافظه‌ی پست‌ها (`state.db`) هم روی همین شاخه نگهداری می‌شود تا بین اجراها گم نشود.
**مخزن باید public باشد.**

### جایگزین: فضای سازگار با S3
اگر می‌خواهید مخزن خصوصی بماند:
```yaml
storage:
  provider: "s3"
  bucket: "insta-media"
  public_base_url: "https://pub-xxxx.r2.dev"
  endpoint_url: "https://<ACCOUNT_ID>.r2.cloudflarestorage.com"
  region: "auto"
```
Cloudflare R2 تا ۱۰ گیگ رایگان است. سرویس‌های ایرانی (آروان‌کلود، لیارا) هم سازگار با
S3 هستند و فقط `endpoint_url` فرق می‌کند.

## اجرا

```bash
python main.py doctor      # همه‌چیز درست تنظیم شده؟
python main.py preview     # یک پست بساز ولی منتشر نکن (خروجی در پوشه output/)
python main.py run         # اجرای واقعی
python main.py quota       # چند پست از سهمیه ۲۴ ساعته مصرف شده
python main.py history     # پست‌های اخیر
```

**اول چند بار `preview` بزنید.** تصاویر و کپشن‌ها را ببینید، `config.yaml` را تنظیم
کنید تا لحن و ظاهر دلخواهتان شود. وقتی راضی بودید، در `config.yaml`:

```yaml
safety:
  dry_run: false
```

## زمان‌بندی روزانه

### گزینه ۱ — cron روی سرور (پیشنهادی)
```bash
crontab -e
```
```cron
# ساعت ۲۱:۰۰ به وقت تهران
0 21 * * *  /home/user/insta-autopost/scripts/run_daily.sh
# تمدید توکن، هر دوشنبه
0 4 * * 1   /home/user/insta-autopost/scripts/refresh_token_cron.sh
```
مطمئن شوید timezone سرور روی تهران است: `sudo timedatectl set-timezone Asia/Tehran`

### گزینه ۲ — GitHub Actions (بدون سرور، پیشنهادی)
دو فایل در `.github/workflows/` آماده است: یکی پست روزانه، یکی تمدید هفتگی توکن.
کافی است در تنظیمات مخزن، بخش **Secrets and variables → Actions**، این‌ها را اضافه کنید:

| Secret | ضروری؟ |
|---|---|
| `IG_USER_ID` | بله |
| `IG_ACCESS_TOKEN` | بله |
| `LLM_API_KEY` | بله |
| `TELEGRAM_BOT_TOKEN` · `TELEGRAM_CHAT_ID` | توصیه می‌شود |
| `GH_PAT` | اختیاری — برای تمدید کاملاً خودکار توکن |

`GH_TOKEN` را گیت‌هاب خودش می‌سازد؛ لازم نیست چیزی تعریف کنید.

> زمان‌بندی cron در GitHub Actions با UTC کار می‌کند و ممکن است تا چند ده دقیقه
> تأخیر داشته باشد. برای پست روزانه اهمیتی ندارد.

## محدودیت‌ها و نکات مهم

**سهمیه انتشار:** هر اکانت در بازه‌ی متحرک ۲۴ ساعته سقف مشخصی برای انتشار از طریق API
دارد (در مستندات فعلی متا ۱۰۰ پست). ربات قبل از هر انتشار سهمیه واقعی را از
`content_publishing_limit` می‌پرسد و اگر پر بود منتشر نمی‌کند. یک سقف محلی محافظه‌کارانه
هم در `instagram.daily_post_cap` تعیین شده است.

**فرمت‌ها:** API فقط **JPEG** می‌پذیرد (PNG و WebP نه). کاروسل بین ۲ تا ۱۰ اسلاید.

**چیزهایی که API پشتیبانی نمی‌کند:** تگ محصول فروشگاه اینستاگرام، تگ محتوای برندی،
فیلترها، و تگ کردن کاربران در کاروسل.

**استوری:** با `media_type=STORIES` پشتیبانی می‌شود ولی در این نسخه فعال نیست.

**ریلز:** کلاینت متد `publish_reel` را دارد، ولی چون تولید خودکار ویدیو نیاز به
سرویس جداگانه دارد، در تقویم پیش‌فرض غیرفعال است. اگر ویدیو آماده دارید، URL عمومی
آن را به `publish_reel` بدهید.

## توصیه‌های عملی

انتشار کاملاً خودکار سریع است ولی یک ریسک دارد: اگر مدل یک بار محتوای نامناسب یا
اشتباه بنویسد، مستقیم روی پیج می‌رود. سه لایه محافظت در پروژه گذاشته شده:

1. `banned_topics` در `config.yaml` — موضوعاتی که مدل حق ندارد درباره‌شان بنویسد
2. `catalog.json` — مدل حق ندارد قیمت یا ویژگی‌ای بسازد که اینجا نیست
3. اطلاع‌رسانی تلگرام — هر پست منتشرشده با لینک برایتان ارسال می‌شود

اگر خواستید محافظه‌کارتر باشید، `dry_run: true` بگذارید و پست‌ها را در `output/`
ببینید و دستی تأیید کنید. یا cron را طوری تنظیم کنید که پست را ۳ ساعت زودتر بسازد و
یک اجرای دوم آن را منتشر کند (کافی است `run` را به دو مرحله تقسیم کنید).

**برای شروع، روزی یک پست کافی است.** الگوریتم اینستاگرام کیفیت و ثبات را بیشتر از
تعداد پاداش می‌دهد.
